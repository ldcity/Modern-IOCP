# Cross-Agent Development

공용 기록을 대화 내용보다 우선한다. 저장소 루트의 `.ai/README.md`(실행 계약·규범 우선순위), `.ai/CONSTITUTION.md`, `.ai/tasks/INDEX.md`를 읽는다.
`seamless-world/` 작업이면 `seamless-world/ROADMAP.md` 가 정본이고, 같은 폴더 `CLAUDE.md` 가
**역할 예외**(Claude 는 구현자가 아니라 조언자)를 정의한다 — 그 프로젝트에서는 이 스킬의 구현 절차를
Claude 가 수행하지 않는다.

## 1. 역할과 기준선

- 작업 문서에서 구현 담당자와 리뷰 담당자를 확인한다.
- 역할이 없으면 `Implementer: Claude`, `Reviewer: Codex`를 기본값으로 기록한다.
- Codex는 사용자가 해당 task의 구현을 명시적으로 맡기지 않는 한 리뷰 역할을 유지한다.
- Claude는 사용자가 해당 task의 리뷰를 명시적으로 맡기지 않는 한 구현 역할을 유지한다.
- 시작 전에 대상 저장소, 현재 브랜치, 기준 커밋, 미커밋 변경을 기록한다.
- 다른 에이전트나 사용자의 변경을 덮어쓰지 않는다.

## 2. 구현 전 명세

비단순 변경은 `.ai/tasks/TEMPLATE.md`로 작업 문서를 만든다. 최소한 목표, 비목표, 완료 조건, 영향 범위와 검증 방법을 적는다.

네트워크·동시성·영속성·성능에 영향을 주면 다음 불변식도 명시한다.

- 객체와 버퍼의 소유자 및 수명
- 상태를 변경할 수 있는 스레드
- 입력 경계와 실패 처리
- 종료, 취소, 재시도와 backpressure
- 성능 기준선과 회귀 허용치

해결책을 정당화하기 전에 문제 증거를 먼저 남긴다.

## 3. 구현

- 완료 조건을 만족하는 가장 작은 수직 변경부터 만든다.
- YAGNI와 KISS를 우선하고, 세 번째 실제 중복 전에는 성급한 추상화를 피한다.
- 소유권, 스레드 경계와 실패 처리를 코드에서 드러낸다.
- 성능을 이유로 안전성을 생략하지 않는다. 측정되지 않은 최적화는 별도 가설로 남긴다.
- 작업 범위를 넓혀야 하면 먼저 작업 문서의 범위와 이유를 갱신한다.

## 4. 구현자 검증과 인계

- 변경 위험에 비례해 빌드, 테스트, 정적 분석 또는 벤치마크를 실행한다.
- 실행한 명령, 결과, 실행하지 못한 검사와 이유를 작업 문서에 기록한다.
- 수정 파일, 핵심 결정, 알려진 위험과 리뷰 집중 지점을 인계란에 남긴다.
- 검증하지 않은 동작이나 성능을 완료됐다고 쓰지 않는다.

## 5. 독립 리뷰

기본 리뷰 담당자인 Codex는 Claude의 결론을 답으로 간주하지 않는다.

1. 기준 커밋부터 diff와 관련 호출 경로를 직접 읽는다.
2. 완료 조건과 불변식을 각각 확인한다.
3. 가능한 검사를 독립 실행한다.
4. `.ai/reviews/TEMPLATE.md` 형식으로 파일·라인·재현 근거가 있는 발견을 기록한다.
5. `Approve`, `Request changes`, `Blocked` 중 하나로 판정한다.

리뷰 중 즉시 코드를 고치지 않는다. 먼저 발견을 기록하고 Claude의 후속 구현 task로 돌려보낸다. 사용자가 Codex에 수정을 명시적으로 재배정한 경우에만 별도 변경으로 처리한다.

## 6. 완료 조건

완료 조건이 충족되고, 검증 증거가 있으며, 리뷰의 차단 발견이 해결되었을 때만 작업을 `Done`으로 바꾼다. 에이전트가 두 개 사용됐다는 사실만으로 교차검증이 성립하지 않는다.
